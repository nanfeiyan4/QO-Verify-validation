
==============================================================================
§3.2  Self-join of Group-By  <=>  CASE 条件聚合
==============================================================================

------------------------------------------------------------------------------
  Query 4（self-join）  vs  Query 5（条件聚合 + HAVING）
------------------------------------------------------------------------------
  LHS 的 memo:
      G1  S.1 Get(sales)
      G2  YT.1 GBAgg{GB=cust,yr;agg=SUM(amt)}(G1)
      G3  F1.1 FILTER{yr=2000}(G2)
      G4  F2.1 FILTER{yr=2001}(G2)
      G5  Q4.1 JOIN[R1.cust=R2.cust](G3,G4)
  RHS 的 memo:
      G1  S.1 Get(sales)
      G2  YT.1 GBAgg{GB=cust,yr;agg=SUM(amt)}(G1)
      G3  V1.1 GBAgg{GB=cust;f1=MAX(CASE yr=2000 THEN amt);f2=MAX(CASE yr=2001 THEN amt);c1=SUM(CASE yr=2000 THEN 1 ELSE 0);c2=SUM(CASE yr=2001 THEN 1 ELSE 0)}(G2)
      G4  Q5.1 FILTER{cust IS NOT NULL AND c1>0 AND c2>0}(G3)

  [规则集不含 §3.2 pivot 规则]  QO-Verify => Unknown
  [把 §3.2 pivot 规则 加入规则集]  QO-Verify => True
      G5~G4 命中: RULE32 == Q5.1
          G6~G3 命中: RULE32.V1 == V1.1
              G2~G2 命中: YT.1 == YT.1
                  G1~G1 命中: S.1 == S.1

==============================================================================
§3.3  Subsumed scalar aggregate subquery  <=>  Outer Join 上的标量聚合
==============================================================================

------------------------------------------------------------------------------
  Query 6（两个标量子查询）  vs  Query 7（LOJ + 条件聚合）
------------------------------------------------------------------------------
  LHS 的 memo:
      G1  S.1 Get(sales)
      G2  P.1 Get(promotion)
      G3  PF.1 FILTER{ch='Y'}(G2)
      G4  J.1 JOIN[s.promo=p.pk](G1,G3)
      G5  A1.1 GBAgg{GB={};agg=SUM(price)}(G1)
      G6  A2.1 GBAgg{GB={};agg=SUM(price)}(G4)
      G7  Q6.1 CROSS{scalar x scalar}(G5,G6)
  RHS 的 memo:
      G1  S.1 Get(sales)
      G2  P.1 Get(promotion)
      G3  PF.1 FILTER{ch='Y'}(G2)
      G4  LOJ.1 LOJ[s.promo=p.pk](G1,G3)
      G5  Q7.1 GBAgg{GB={};a1=SUM(price);a2=SUM(CASE p.pk IS NOT NULL THEN price ELSE NULL)}(G4)

  [规则集不含 §3.3 LOJ 规则]  QO-Verify => Unknown
  [把 §3.3 LOJ 规则 加入规则集]  QO-Verify => True
      G7~G5 命中: RULE33 == Q7.1
          G8~G4 命中: RULE33.LOJ == LOJ.1
              G1~G1 命中: S.1 == S.1
              G3~G3 命中: PF.1 == PF.1
                  G2~G2 命中: P.1 == P.1

==============================================================================
小结
==============================================================================
  两条规则都复现出同样的现象：
      * 规则不在规则集里  -> Unknown（算法本身没错，是"证明链断了"）
      * 规则加进去        -> True（算法一行没改）

  §3.2 的关键：GBAgg(a∪b) 使 (a,b) 成为 key，从而 MAX(CASE …) 每组至多一个非 NULL；
               并用 c1/c2 计数复现 inner join 的"两年都得有"，a IS NOT NULL 复现 NULL 语义。
  §3.3 的关键：LOJ 保基数（依赖 FK->PK），S.k 非 NULL 恰好标记"匹配且通过过滤"。
  这两条前提都是**约束相关**的，玩具模型无法表达 —— 下一段用 SQL 级 fuzz 去检验前提被破坏时会怎样。
